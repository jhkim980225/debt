# Feature: Community Board

## 목적

빚 상환은 외로운 여정. **같은 처지 사람들과 정보 공유 + 응원**으로 동기 유지. 동시에 **잘못된 금융 조언과 우울한 분위기**의 위험을 관리.

## 우선순위

**Phase 3**

## 핵심 원칙

1. **게시판 형식 (디시/뽐뿌 스타일)**: 기존 한국 사용자에게 익숙한 패턴
2. **익명 닉네임 기본**: 빚은 민감 정보, 실명 강제 X
3. **금액은 범위만**: "1000만원대" 같은 표현. 정확 금액 노출 X
4. **리더보드/랭킹 없음**: 비교 문화 차단
5. **카테고리로 구조화**: 정보 + 자유 + 인증 + 질문 분리

## 사용자 스토리

> 비슷한 빚 상황인 사람들의 글을 보고, 절약 정보를 얻고, 가끔 내 진전을 공유하면서 외롭지 않게 가고 싶다.

## 진입 경로

- 하단 탭바의 "함께" 또는 "커뮤니티" 탭

## 화면 1: 게시판 메인

### 헤더
- "게시판" 제목
- 우측: 검색 아이콘 + 글쓰기 [+] 아이콘

### 카테고리 필터 (가로 스크롤 칩)
- 칩 8개:
  1. **전체** (디폴트)
  2. 자유
  3. 질문
  4. 인증
  5. 절약
  6. 부업
  7. 금융정보
  8. 공포의빚

### 정렬 + 글 수
- 좌측: 정렬 칩 3개
  1. **최신순** (디폴트)
  2. 인기순 (좋아요+조회수 가중치)
  3. 댓글많은
- 우측: 전체 글 수 (예: "5,284 글")

### 게시글 목록

각 게시글 행:
- 카테고리 라벨 (색상 다름)
- 특수 라벨: "공지" / "HOT" / "에디터픽" (조건부)
- 제목 + 댓글 수 (빨간 [38] 형식, 디시 스타일)
- 메타: 작성자 닉네임 · 시간 · 조회수 · 좋아요

### 인증글 강조
- `cat == 'certify'`인 경우 배경색 살짝 다르게 (`#FFFEF8`)
- 시각적으로 떠오르되 너무 튀지 않게

### HOT 라벨 자동 부여 조건
- 조회수 >= 1000 OR 좋아요 >= 100
- 작성 7일 이내

### 에디터픽 (수동)
- 운영자가 검증한 글에 부여
- 잘못된 금융 정보 차단용
- 회색 작은 라벨

## 화면 2: 게시글 상세

### 헤더
- 좌측: ← 뒤로
- 우측: ⋯ 메뉴 (신고, 공유, 작성자면 수정/삭제)

### 본문
- 카테고리 라벨
- 제목 (큰 글씨)
- 작성자 정보:
  - 닉네임 + streak 배지 (있으면)
  - 시간
- 본문 내용
- 첨부 이미지 (있으면)
- 인증글이면: 진행률 / 빚 범위 표시 카드

### 액션 바
- 좋아요 (♥ + 카운트)
- 댓글 (○ + 카운트)
- 공유

### 댓글 영역
- "댓글 N개" 헤더
- 정렬: 최신순 / 좋아요순
- 댓글 카드들
  - 작성자 닉네임 + streak 배지
  - 본문
  - 시간 + 좋아요 + 답글 버튼
- 대댓글 (1단계 들여쓰기)

### 댓글 입력
- 하단 고정
- 작성자 아바타 + 입력칸 + 전송 버튼
- "익명으로 작성" 토글

## 화면 3: 글쓰기

### 헤더
- 좌측: × 닫기 (확인 다이얼로그)
- 우측: "올리기" 버튼 (필수 항목 채워지면 활성)

### 카테고리 선택 (필수)
- 7개 칩 중 선택 (공지 제외)
- 각 카테고리 선택 시 본문 영역에 가이드 노출:
  - 인증: "어떤 진전이 있었나요? (사진 첨부 권장)"
  - 질문: "구체적으로 적어주시면 좋은 답이 와요"
  - 절약: "실제로 효과 본 노하우를 공유해주세요"
  - 등

### 익명 작성 토글
- "익명으로 작성" 체크박스
- 켜면 작성자 표시 = "익명"
- 자유, 자기 빚 푸념 등에 유용

### 제목
- 1줄 입력
- 5-100자

### 본문
- 멀티라인 (최소 5줄)
- 마크다운 X (단순 텍스트)
- 최대 5000자

### 이미지 첨부 (선택)
- 최대 4장
- 인증글에서 인증샷에 사용
- 자동 압축 (1MB 이하)

### 인증글 추가 정보 (조건부)
카테고리 = certify일 때:
- 빚 범위 자동 표시 (사용자 데이터 기반)
- 진행률 자동 표시
- 사용자가 수정/삭제 가능

|----|------|-----------|------------|

| `question` | 질문 | `pinkLight` | `pinkDark` |

| `save` | 절약 | `successLight` | `success` |

| `horror` | 공포의빚 | `dangerLight` | `dangerDark` |

## 닉네임 시스템

`docs/glossary.md` 참조. 자동 생성 패턴:
- 자연 + 동작/명사 조합
- 예: "햇살모은이", "조용한걸음", "바람부는언덕"
- 가입 시 5개 후보 + "다른 추천" 버튼

### 변경
- 30일에 1회 변경 가능
- 욕설/실명 필터 (서버)

### 익명 작성
- 작성자 = "익명"으로만 표시
- 단, 본인은 자기 익명글 식별 가능
- 댓글도 익명 작성 가능

## 좋아요 (Likes)

- 게시글 + 댓글 둘 다 가능
- 한 번만 (취소 가능)
- 카운트 실시간 갱신

## 신고 (Reports)

### 트리거
- 게시글/댓글의 ⋯ 메뉴
- "신고하기" 선택

### 신고 사유 (라디오)
- 스팸/광고
- 욕설/혐오
- 잘못된 정보
- 도배
- 기타 (자유 입력)

### 처리
- 서버에 Report 엔티티 저장
- 같은 글 신고 3건 누적 → 자동 검토 큐 진입
- 운영자 검토 후 삭제/유지 결정

## 검색

### 검색 가능 영역
- 게시글 제목 + 본문
- 닉네임

### 필터 (검색 결과 화면)
- 카테고리
- 기간

## 빈 상태

| 상황 | 메시지 |
|------|--------|
| 첫 진입 (글 없음) | "아직 글이 없어요. 첫 글을 써볼래요?" |
| 카테고리 필터 결과 없음 | "{카테고리}에 글이 없어요" |
| 검색 결과 없음 | "검색 결과가 없어요" |
| 차단된 글만 있음 | "표시할 글이 없어요" |

## 푸시 알림

| 종류 | 시점 | 내용 |
|------|------|------|
| 댓글 받음 | 즉시 | "{닉네임}님이 회원님 글에 댓글을 달았어요" |
| 답글 받음 | 즉시 | "{닉네임}님이 회원님 댓글에 답글을 달았어요" |
| 좋아요 받음 | 일별 모음 (스팸 방지) | "회원님 글에 X명이 좋아요를 눌렀어요" |
| 공지 등록 | 즉시 | "새로운 공지가 등록됐어요" |

알림 ON/OFF는 설정에서 가능.

## 콘텐츠 정책

### 금지 콘텐츠
1. **광고/홍보** (대출 상품, 투자 권유 등)
2. **욕설/혐오 발언**
3. **개인 식별 정보** (실명, 전화번호, 계좌번호)
4. **도배** (같은 내용 반복)
5. **잘못된 금융 정보** (예: "리볼빙 추천")
6. **불법 정보** (대포통장, 사채 알선 등)

### 운영 정책
- 1차 위반: 경고 + 글 삭제
- 2차 위반: 7일 정지
- 3차 위반: 영구 정지
- 심각한 경우: 즉시 영구 정지

### 자동 필터
- 키워드 필터 (욕설, 광고 키워드)
- 클라이언트에서 1차 + 서버에서 2차

## Edge Cases

### 글 작성 중 앱 종료
- 자동 저장 (드래프트)
- 다음 진입 시 "작성 중인 글이 있어요. 이어서 쓸까요?"

### 매우 긴 본문 (5000자 초과)
- 입력 차단 + "최대 5000자까지 입력 가능해요"

### 이미지 업로드 실패
- 재시도 버튼
- 글은 저장 (이미지는 나중에 추가 가능)

### 작성자 차단된 사용자
- 그 사용자 글 안 보임
- 댓글도 안 보임
- 차단 해제 시 다시 보임

### 삭제된 글에 댓글
- "삭제된 글이에요" 표시
- 댓글은 그대로 남음 (또는 같이 삭제, 정책 결정 필요)

### 본인이 자기 글에 좋아요
- 허용
- 단, 카운트는 별도 표시 안 함 (그냥 ♥ 색만 변경)

### 오프라인
- 읽기 모드 (캐시된 글)
- 쓰기 시도 시 "온라인 연결이 필요해요"

## 백엔드 (Supabase)

### 테이블
- `posts`
- `comments`
- `likes`
- `reports`
- `community_users` (닉네임, 차단 목록 등)

### RLS 정책
- 본인 글만 수정/삭제
- 차단된 글은 운영자만 조회
- 익명 작성 시 author_id는 백엔드에만 보관, 클라이언트에 안 노출

### 실시간 (Phase 4)
- 좋아요/댓글 실시간 업데이트 (Supabase Realtime)
- Phase 3에서는 폴링 또는 진입 시 갱신
