# Feature: Payment Record

## 목적

사용자가 빚을 갚은 사실을 앱에 기록. **하루 30번 사용해도 부담 없게** 빠르고 즐거운 경험이 핵심.

## 우선순위

**Phase 1 (출시 필수)**

## 핵심 원칙

1. **10초 안에 기록 완료** (목표 KPI)
2. **즉각적 시각화**: 입력 즉시 진행률 변화 보여주기 → 도파민 트리거
3. **우선순위 빚 자동 선택**: 사용자가 매번 고를 필요 없게
4. **자주 쓰는 금액 칩**: 키패드 안 띄워도 톡톡으로 끝

## 사용자 스토리

> 매일 빚을 갚을 때마다, 앱을 켜고 빠르게 기록한 후 작은 성취감을 느끼고 싶다.

## 진입 경로

1. **대시보드의 [+ 상환 기록] 버튼** (가장 흔한 경로)
2. **빚 상세 화면의 [+ 상환 기록]** (특정 빚에 갚을 때)
3. **푸시 알림 → 딥링크** (`debtapp://record`)

## 화면 구성 (모달, Bottom Sheet)

### 헤더
- 좌측: × 닫기
- 중앙: "상환 기록"
- 우측: 오늘 날짜 (예: "5월 1일")

### 섹션 1: 빚 선택
- 라벨: "어디에 갚았어요?"
- 빚 리스트 (라디오, 단일 선택)
- 각 빚 행:
  - 카테고리 색 점
  - 빚 이름
  - 우측: 잔액 + 이자율
  - 우선순위 빚이면 "우선순위" 배지

#### 자동 선택 규칙
1. **진입 경로가 빚 상세 화면**: 그 빚 자동 선택
2. **대시보드에서 진입**: 우선순위 빚 자동 선택
3. **딥링크 진입**: 우선순위 빚 자동 선택

#### 빚이 1개일 때
- 선택 UI 숨기기 (자동 선택)
- "신용카드 A에 갚기" 처럼 헤더에 표시

### 섹션 2: 금액 입력
- 라벨: "얼마 갚았어요?"
- **큰 입력칸** (강조):
  - 우측 정렬 "원"
  - 폰트 크게 (`displayAmountMedium` 정도)
  - 자동 천단위 콤마
  - 텍스트 가운데 정렬
- 숫자 키패드 자동 표시

#### 빠른 선택 칩 (3개)
선택된 빚에 따라 자동 생성:
- "최소 X만원" (해당 빚의 `minimumPayment` 기반)
- "목표 X만원" (해당 빚의 `targetPayment`, 디폴트 강조)
- "+10만원 더" (목표보다 10만원 더 갚기)

#### 금액이 잔액보다 클 때
- 자동 알림: "남은 금액(X원)보다 많아요. 정확히 X원만 기록할까요?"
- 선택지: "정확히 갚기" / "전부 기록" (over-payment 허용)

### 섹션 3: 즉시 변화 미리보기
- **이 카드가 핵심 도파민 트리거**
- 녹색 톤 카드
- 헤드라인: "이렇게 바뀌어요"
- 가로 정렬 2개:
  - 좌측: "남은 잔액" → 새 잔액 (큰 글씨)
  - 화살표 →
  - 우측: "진행률" → 새 진행률 (% + ▲ 변화량)
- **금액 입력에 따라 실시간 갱신**

### 섹션 4: 날짜 선택
- 라벨: "언제 갚았어요?"
- 칩 3개:
  1. **오늘** (디폴트, 강조)
  2. 어제
  3. 날짜 선택 (캘린더 모달)

#### 과거 날짜 입력 시
- 최대 30일 전까지 허용
- 너무 오래된 기록은 데이터 무결성 깨질 수 있음

### 섹션 5: 메모 (선택, 펼침)
- `<details>` 토글, 닫혀있는 게 디폴트
- 펼치면: 텍스트 입력칸 (1줄)
- 플레이스홀더: "예: 보너스로 추가 상환"
- 길이: 0-50자

### 섹션 6: 동기부여 인용구
- 보라 톤 카드 (작게)
- 시리프 폰트, 이탤릭
- 카피 풀에서 랜덤:
  - "오늘의 30만원은 미래의 60만원을 아끼는 일이에요."
  - "한 걸음 한 걸음, 자유에 가까워지고 있어요."
  - "오늘의 선택이 미래를 만들어요."
- 입력 금액 기반 동적 카피 (선택, Phase 2)

### 하단 버튼
- 좌측 (1/3): "취소"
- 우측 (2/3): "기록 완료 ✓" (메인)

## 기록 후 처리

### 1. 데이터 저장
- `Payment` 엔티티 생성 + Hive 저장
- 해당 `Debt`의 `currentBalance` 갱신
- 잔액이 0이면 `isPaidOff = true` + `paidOffAt` 설정

### 2. 트리거되는 이벤트
- 연속 기록 (`streak`) 갱신:
  - 오늘 첫 기록이면 +1
  - 어제도 있으면 연속 유지
  - 어제 없었으면 1로 리셋 (오늘부터 다시)
- 배지 체크 (`07-badges-motivation.md` 참조)
- 우선순위 재계산 (필요 시)

### 3. 사용자 피드백

#### 일반 기록
- 모달 닫기
- 대시보드로 복귀
- 토스트 또는 작은 애니메이션:
  - "기록 완료! +9% 진행 ✨"

#### 배지 획득 시
- 모달 위에 배지 획득 다이얼로그
- 별 효과 + 배지 시각화
- 카피: "새 배지: {배지이름}"
- "확인" 버튼 → 대시보드

#### 빚 졸업 시 (잔액 0 도달)
- **특별 화면** (`features/02-debt-register.md`의 졸업 화면 참고)
- 컨페티 + "축하해요!"
- "{빚이름} 졸업했어요!"
- 다음 빚으로 자동 우선순위 재계산
- 게시판 인증 공유 옵션

## 데이터 무결성

### 결제 기록 수정/삭제
- 기록 후 24시간 내에만 수정 가능
- 삭제는 Phase 2에서 (실수로 누른 경우)
- 수정 시 잔액 재계산 + 연관 데이터 갱신

### 동시성
- 같은 빚에 빠르게 여러 번 기록 시도
- 트랜잭션으로 처리 (Hive에서 순차 처리)

## 카피 디테일

### 톤
- 친구가 옆에서 응원하는 느낌
- 명령형 X
- 권유형 + 격려 O

### "이렇게 바뀌어요" 카드
- 의도: 추상적 행동(돈 내기)을 구체적 진전으로 시각화
- 즉각성이 핵심: 입력하는 동안 실시간 갱신

### 인용구
- 가르치려 들지 않기
- 시적이지만 단순한 언어
- 한국어 자연스러운 표현

## Edge Cases

### 빚이 1개도 없을 때
- 이 화면 진입 자체 차단
- 대시보드에서 [+ 상환 기록] 버튼 비활성화 또는 숨김

### 모든 빚이 졸업했을 때
- 진입 차단
- "갚을 빚이 없어요" 메시지

### 음수/0원 입력
- 0원: 거부, "1원 이상 입력해주세요"
- 음수: 키패드에서 입력 불가

### 매우 큰 금액 (잔액의 100배 이상)
- 확인 다이얼로그: "정말 X원이 맞나요? 한 번 더 확인해주세요"
- 의도: 실수 방지 (콤마 잘못 입력 등)

### 기록 후 즉시 다시 기록
- 정상 처리. 같은 날 여러 번 갚을 수 있음
- 연속 기록은 하루에 한 번만 +1

### 미래 날짜 선택
- 거부. 오늘까지만 가능

### 해당 빚이 이미 졸업했는데 기록 시도
- 거부. "이미 졸업한 빚이에요"

### 네트워크 오프라인
- Hive는 로컬이라 무관하게 작동
- 단, Supabase 동기화는 큐에 쌓아두고 온라인 시 일괄 전송

## 분석 이벤트

- `payment_record_started` (entryPoint, debtId)
- `payment_record_amount_quick_chip_used` (chipType: 'min', 'target', 'extra')
- `payment_record_completed` (debtId, amount, isExtra, hasNote)
- `payment_record_canceled`
- `payment_record_resulted_in_streak` (newStreakDays)
- `payment_record_resulted_in_badge` (badgeId)
- `payment_record_resulted_in_graduation` (debtId)

## 성능

### 입력 반응성
- 금액 입력 시 미리보기 갱신: 디바운스 100ms
- 너무 즉각적이면 거슬리고, 느리면 연결 끊긴 느낌

### 진행률 계산
- 메모이제이션
- 입력 변경 시에만 재계산
