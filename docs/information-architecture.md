# Information Architecture

앱 화면 구조와 사용자 흐름.

## 화면 트리

```
앱 시작
├── 스플래시 (자동 라우팅)
│   ├── 로그인 안 됨 → 온보딩
│   └── 로그인됨 → 홈 (대시보드)
│
├── 온보딩 (4단계 슬라이드)
│   └── 회원가입 / 로그인
│       ├── 회원가입
│       │   └── 소셜 (카카오/구글/애플/네이버) 또는 이메일
│       ├── 로그인
│       │   ├── 비밀번호 찾기 (3단계)
│       │   └── 자동 로그인
│       └── 완료 → 빚 등록 1단계 (강제)
│
└── 홈 (탭 네비게이션)
    ├── 대시보드
    │   ├── + 상환 기록 (모달)
    │   ├── 시뮬레이션
    │   └── 빚 카드 탭 → 빚 상세
    │       ├── 정보 수정
    │       └── + 상환 기록 (모달)
    ├── 통계
    │   └── 기간 필터 (6개월/올해/전체)
    ├── 배지/여정
    └── 게시판 (커뮤니티)
        ├── 카테고리 필터
        ├── 글쓰기
        ├── 게시글 상세
        │   └── 댓글 작성
        └── 검색

설정 (홈 어딘가에서 진입)
├── 프로필
├── 상환 전략
├── 알림
├── 프라이버시
└── 데이터 관리
```

## 핵심 사용자 흐름

### 1. 첫 사용 (Onboarding Flow)

```
앱 다운로드
→ 스플래시 (3초)
→ 온보딩 슬라이드 1: "빚, 혼자 갚지 마세요"
→ 온보딩 슬라이드 2: "함께 계획하기"
→ 온보딩 슬라이드 3: "매일 응원받기"
→ 온보딩 슬라이드 4: "한 걸음씩 자유에"
→ [시작하기] 버튼
→ 회원가입 화면
→ 소셜/이메일 선택
→ 빚 등록 1단계 (자동 진입, 건너뛸 수 없음)
→ 빚 등록 2단계
→ 등록 완료 축하 화면
→ 대시보드
```

**핵심 KPI**: 회원가입 → 첫 빚 등록 완료율 60% 이상 목표

### 2. 매일 사용 (Daily Flow)

```
앱 열기
→ 대시보드 (자동)
→ [+ 상환 기록] 탭
→ 빚 선택 (우선순위 빚 자동 선택됨)
→ 금액 입력 (목표 금액 자동 채워짐)
→ 날짜 확인 (오늘 자동)
→ [기록 완료] 탭
→ 변화 시각화 + 가능하면 배지 획득 애니메이션
→ 대시보드로 복귀 (진행률 업데이트됨)
```

**핵심 KPI**: 매일 상환 기록까지 10초 이내, 7일 연속 기록 사용자 비율 30% 이상

### 3. 새 빚 추가 흐름

```
대시보드
→ [+] 또는 빚 목록 하단 [+ 빚 추가]
→ 빚 등록 1단계 (필수: 카테고리, 이름, 잔액, 이자율)
→ 빚 등록 2단계 (선택: 결제일, 최소/목표 금액, 알림)
→ 등록 완료 (대시보드로)
```

### 4. 졸업 (특별 흐름)

```
상환 기록 → 잔액이 0이 됨
→ 졸업 축하 화면 (특별 애니메이션)
→ 배지 획득 (firstGraduation 또는 allCleared)
→ 게시판에 인증 공유 옵션
→ 다른 빚이 있으면 우선순위 자동 재계산
→ 모든 빚 완납이면 "자유" 화면 (특별)
```

## 네비게이션 패턴

### 하단 탭 (4개)
| 탭 | 아이콘 | 라벨 |
|----|--------|------|
| 대시보드 | home | 홈 |
| 통계 | chart | 기록 |
| 배지 | trophy | 배지 |
| 게시판 | message | 함께 |

설정은 별도 탭이 아닌 대시보드의 우상단 톱니바퀴 또는 프로필 메뉴에서 접근.

### 모달 (Bottom Sheet)
- 상환 기록
- 빚 등록 (전체 화면 모달)
- 글쓰기
- 빚 정보 수정

### 풀스크린 라우트
- 빚 상세
- 게시글 상세
- 시뮬레이션
- 설정 하위 화면

## 화면 간 데이터 전달

### Provider 기반 (전역)
- 현재 사용자 정보
- 빚 리스트
- 설정값

### 라우트 파라미터 (특정 화면)
- 빚 상세: `debtId`
- 게시글 상세: `postId`
- 댓글 작성 시 답글: `parentCommentId`

## 빈 상태 (Empty States)

각 화면에 빈 상태 디자인 필수.

| 화면 | 빈 상태 메시지 |
|------|--------------|
| 대시보드 (빚 없음) | "첫 빚을 등록해볼까요?" + 등록 버튼 |
| 통계 (데이터 없음) | "상환 기록이 쌓이면 여기에 그래프가 나타나요" |
| 배지 (없음) | "첫 상환을 기록하면 첫 배지를 받아요!" |
| 게시판 (글 없음) | "아직 글이 없어요. 첫 글을 써볼래요?" |
| 검색 (결과 없음) | "검색 결과가 없어요" |

## 에러 상태

| 상황 | 처리 |
|------|------|
| 네트워크 끊김 | "인터넷 연결을 확인해주세요" + 재시도 |
| 서버 에러 | "잠시 후 다시 시도해주세요" |
| 로그인 만료 | 자동 로그아웃 → 로그인 화면 |
| 데이터 손상 | "데이터를 불러올 수 없어요" + 고객센터 안내 |

## 알림 (Push Notification)

| 종류 | 시점 | 내용 |
|------|------|------|
| 결제일 알림 | 결제 3일 전 (사용자 설정) | "신용카드 A 결제일이 3일 남았어요" |
| 동기부여 | 매일 아침 9시 (옵션) | 동기부여 메시지 + 오늘의 진행 상황 |
| 연속 기록 위험 | 밤 9시, 오늘 기록 없을 때 | "연속 기록이 끊기기 전에..." |
| 커뮤니티 반응 | 실시간 (옵션) | "○○님이 회원님 글에 댓글을 달았어요" |
| 배지 획득 | 즉시 | "새 배지를 획득했어요: ○○" |

## 딥링크

- `debtapp://debt/{id}` → 빚 상세
- `debtapp://post/{id}` → 게시글
- `debtapp://record` → 상환 기록 모달

## 접근성

- 모든 인터랙티브 요소 최소 44x44pt
- 색상만으로 정보 전달 금지 (아이콘/텍스트 병기)
- VoiceOver/TalkBack 라벨 모두 작성
- 동적 폰트 크기 지원 (시스템 설정 따라가기)
